# Ghost findings — 2026-05-22

Inventory of issues to fix in ghost and ideas to borrow from muse, gathered
before drafting the next implementation plan. Captures the architecture
review, muse comparison, and the embedding-topics rewrite context.

## Ghost: things to fix

### Architectural (load-bearing)

1. **Slug as bucketing key.** Topic observations bucket by exact-match
   string on a free-text LLM output. Three drift-prevention layers
   (slug-shape rules in extract prompt, KNOWN TOPICS injection,
   `internal/canonicalize` + alias map + resolve-at-read shim) are all
   patches for this one design choice. See
   `docs/specs/2026-05-22-topics-by-embedding.md`. Fix: cluster topics by
   cosine similarity on `.Text` like identity/rule already do; name at
   synthesize time with the smart model.

2. **No fingerprinting of derived artifacts.** Content-hashing covers
   inputs (new transcripts) but not prompt versions, model identity, or
   config. When prompts change, the only way to force recomputation is
   `rm -rf .state/`. This is the root cause of the "annoying to delete
   and re-run during testing" pain. Fix: every artifact carries
   `inputs_hash + prompt_hash + model_id`. Reads check fingerprint;
   mismatch recomputes.

3. **`--stages` leaks implementation into the public CLI.** Stages are
   debugging concerns, not user concerns. `ghost compose --stages
   extract` reads as confused product. Fix: `ghost compose` runs
   end-to-end; stage debugging moves behind a hidden flag or `ghost
   debug …`.

4. **Sources are hardwired to `~/.claude/projects`.** No interface,
   no extension point. Adding opencode/codex/etc later means surgery
   across `internal/transcript/`, `cmd/compose.go`, and the ledger. Fix:
   define a `Source` interface even with one implementation.

5. **Embedding-model config is inconsistent.** Voyage path reads
   `config.Embedding.Model`. Ollama path hardcodes `nomic-embed-text`
   and ignores config (`internal/embedding/ollama.go`). The default
   `voyage-3-lite` in `config.Defaults()` implies Voyage when the actual
   default path is Ollama. Two backends should read the same field.

### README ↔ code divergence (UX, blocks public release)

6. **`refine` stage referenced 4× in README, rejected by code.**
   `cmd/compose.go:262` known stages: `extract`, `canonicalize`,
   `cluster`, `synthesize`. README's cadence table and workflow examples
   tell users to run `--stages cluster,synthesize,refine`. Runtime
   error: `unknown stage "refine"`.

7. **`ghost topics`, `ghost voice`, `ghost config show/edit` documented
   but don't exist.** Actual commands are `ghost show topics`, `ghost
   show core`. No `ghost config` subtree.

8. **`--since`, `--project`, `--verbose` documented or registered but
   never read.** `--verbose` is registered on root in `cmd/root.go:22`
   and never consulted. `--since` and `--project` appear in the README
   flag table and don't exist on `composeCmd`.

9. **Ollama is a hard requirement for `cluster` but missing from README
   Requirements.** `selectEmbedder` falls back to Ollama when
   `VOYAGE_API_KEY` is unset. New users hit connection-refused with no
   upfront warning.

10. **Default `--stages extract` produces no user-visible output.**
    First-run `ghost compose --limit 5` writes observations to `.state/`
    and exits; `ghost show` returns nothing useful. README implies
    end-to-end. Fix lands naturally with item 3 (end-to-end default).

11. **README references unimplemented commands and stale phasing.**
    Drop "Phase 1 / Phase 2 / Phase 3" language. Lead with what ghost
    *is*, not which phase it's in. Add an example
    `~/.ghost/topics/foo.md` so readers see the output. Add license,
    privacy stance, limitations.

### Code hygiene (low priority, batch later)

12. **`firstBalancedObject` duplicated three times.**
    `internal/extract/extract.go:154`,
    `internal/canonicalize/pipeline.go:204`,
    `internal/cluster/canonical.go:138`. Extract to `internal/jsonutil`.

13. **`observationsFileName` double-hashes for no real benefit.**
    `cmd/compose.go:247`. Trim `sha256:` prefix, take 20 chars of
    existing hash; drop the secondary SHA256.

14. **Dead config fields.** `Voice.Enabled` (`config.go:46`) and
    `Batching.DefaultLimit` (`config.go:37`) are never read. Wire or
    delete.

15. **Per-transcript ledger saves in worker loop are redundant.**
    `runExtract` saves the ledger inside the per-transcript goroutine
    under `mu`, and again at line 219. The per-transcript saves are
    unnecessary I/O; final save covers them.

16. **`estimateCluster` measures byte size, not LLM call volume.**
    Token-heavy work in cluster is the canonicalizer LLM calls, not
    embedding. Estimate misses the dominant cost. (Becomes moot when
    canonicalize is deleted as part of item 1.)

## Muse: ideas to adopt now

1. **Fingerprint-based cache invalidation.** Every artifact stores
   `hash(inputs, prompt_versions, model_id)`. On read, fingerprint
   mismatch triggers recomputation. Self-invalidating dependency chain.
   `--reobserve` / `--relabel` exist as explicit overrides for prompt
   iteration. This is the durable fix for ghost's "delete state to
   re-test" pain. See `../muse/designs/004-clustered-compose.md` §
   Caching.

2. **Flat CLI surface.** `muse compose` is end-to-end. No `--stages`
   flag in the public surface. Stages are internal. Apply directly to
   ghost — drop `--stages` from public, move to hidden debug path.

3. **Source interface.** Muse supports claude-code, opencode, kiro,
   codex, github, slack as first-class sources, plus `muse-{name}`
   external plugins on `$PATH`. Ghost should define the interface even
   with one implementation. Defer the plugins-on-PATH extension until
   there's a concrete second source.

4. **Per-source observe prompts.** Muse routes to different observe
   prompts by source type — AI conversations vs human conversations
   (Slack, GitHub) — because the signal differs. Ghost has only AI
   transcripts today, but the routing point is the same place the
   Source interface lands. Cheap to design in now.

5. **`--reobserve` / `--recluster` / `--resynth` flags.** Explicit
   debugging overrides that skip fingerprint comparison. Lets you
   iterate on a prompt without nuking state. Pairs with item 1.

## Muse: ideas to consider later (defer)

1. **MCP server mode (`ghost listen`).** Muse exposes itself over MCP
   so any agent can query the brain live. For ghost, this would
   complement the static `@`-include with live retrieval — agents could
   ask "what does Sarah think about X?" mid-conversation without
   precomputed include paths. Design-in (don't preclude); build when
   the static include model starts feeling limiting.

2. **`ghost eval`.** First-class eval command. Without it, every prompt
   change is a vibes-driven A/B. Build when the next round of prompt
   iteration starts and the absence is felt. See
   `../muse/designs/006-incremental-distillation-eval.md`.

3. **`ghost sync local s3` / `ghost sync s3 local`.** Cross-machine
   sync via S3 bucket. Useful for work+personal use across multiple
   machines. Not urgent.

4. **Theme consolidation as an explicit step.** Muse does label → theme
   (consolidate vocabulary) → group. Becomes moot if ghost adopts
   embedding-based topic clustering (item 1 in fixes), because content
   embeddings do this implicitly. Keep on the radar in case the
   embedding approach produces fragmented clusters in practice.

5. **Map-reduce composition as a fallback strategy.** Muse keeps two
   composition methods (clustering vs map-reduce) permanently. Ghost
   doesn't need this today but the pattern is useful: per-output-shape
   composition strategy, selectable at runtime.

6. **Conversation compression for context window.** Muse compresses
   conversations (strip code blocks, collapse tool output, truncate
   assistant messages) before observe. Ghost extracts per-message
   today; if extract starts running into context limits, borrow the
   compression strategy. See `../muse/designs/009-observations.md` §
   Compression.

## Things ghost does right (keep)

- Atomic tmpdir/rename write pipeline (`internal/synthesize/pipeline.go`).
- Per-kind output decomposition: identity / rules / topics as separate
  files. Better fit for Claude Code's `@`-include model than muse's
  single `muse.md`.
- Topic index with triggers enabling selective context loading via the
  skill. The Claude-Code-native moat.
- Content-hash gating in the ledger (`internal/ledger/`).
- Package boundaries and file sizes. Ghost is 5,200 LoC across many
  small files; muse's `internal/compose/clustered.go` is 1,734 lines
  alone.
- Local-first stance: `claude -p` shell-out instead of API key.
  Foundational difference from muse — this is why ghost exists at all.
- Errors over silent fallbacks at the boundary (Ollama "model may not
  be pulled" message, cluster's "run synthesize first" gating).

## Cross-cutting decision: bundle the design, execute in chunks

The embedding-topics rewrite, fingerprint-everything, and flat-CLI
change all touch cache layout, stage gating, and the CLI. Design the
end state once so the cache doesn't get rewritten twice. Land it in
small chunks with verification between each — Claude works better on
small chunks, and each chunk leaves ghost usable.

Out of scope: MCP server, eval, sync, conversation compression. Each
earns its place with a concrete trigger.

### Chunk 1: Source interface

Smallest, no behavior change. Pure refactor.

- Extract `internal/transcript/` discovery behind a `Source` interface
- One implementation: `ClaudeCodeSource` wrapping current behavior
- No CLI changes, no cache layout changes

Verifies: existing tests pass; `ghost compose` produces identical
output. Done when the interface is in place and there's a clear seam
for adding a second source later.

### Chunk 2: Fingerprint cache

Foundational. Enables every later chunk to iterate on prompts without
nuking state.

- Add `inputs_hash + prompt_hash + model_id` to observation, cluster,
  and topic artifacts
- Cache reads check fingerprint; mismatch triggers recomputation
- Add `--reobserve`, `--recluster`, `--resynth` flags as explicit
  overrides for debugging
- **Resolve `Conversation.Source` divergence risk (from chunk 1
  review).** Today the field is set by `ClaudeCodeSource.Discover`
  from `s.Name()`; there is no enforcement that callers constructing
  `Conversation` directly stamp it correctly. Once fingerprints
  incorporate source name, divergence becomes a real bug. Add
  `source.NewConversation(src Source, id, project string, modTime
  time.Time) Conversation` that always stamps `Source` from
  `src.Name()`; migrate the one current construction site
  (`claudeCodeSource.Discover`) and any new ones in chunk 2 to use
  it. Five lines, kills a class of bug before it ships.

Verifies: change an extract prompt, rerun `ghost compose`, observations
recompute automatically with no manual `rm`. Done when prompt iteration
no longer requires touching `.state/`.

### Chunk 3: Embedding-based topics

The disruptive one. Implements
`docs/specs/2026-05-22-topics-by-embedding.md`.

- Delete `internal/canonicalize/`, KNOWN TOPICS plumbing, slug-shape
  rules in extract prompt, `slug_aliases.json` resolve-at-read shim
- Cluster topic observations by cosine similarity on `.Text` (drop
  SubKey equality for `kind: topic`)
- Synthesize emits `{slug, body}` from one smart-model call per
  cluster
- Separate cosine threshold for topics vs identity/rule

Depends on chunk 2 — corpus rebuild is much less painful with
fingerprints in place. Verifies: rerunning twice on the same corpus
produces stable topic slugs; obvious synonym cases (`docs` vs
`documentation`) land in one topic.

### Chunk 4: Flat CLI

- `ghost compose` runs end-to-end by default (no `--stages` needed)
- Move `--stages` behind hidden debug path or remove entirely
- Fix command names referenced in README to match code (`ghost show
  topics` etc.)
- Remove dead flags (`--verbose`, `--since`, `--project`)

Independent of chunk 3 but feels wrong to flatten the CLI while stages
are still load-bearing for testing. Verifies: a new user can run
`ghost compose` cold and get a populated `~/.ghost/`.

### Chunk 5: README + public-repo pass

Lands last because the surface keeps moving until chunk 4.

- Lead with what ghost *is* in one sentence
- Add Ollama to Requirements
- Drop phase language and unimplemented commands
- License file, privacy stance, limitations
- Example `~/.ghost/topics/foo.md` so readers see the output
- Move internal design docs out of public path or into clearly-marked
  `docs/internal/`

Verifies: a colleague reads it cold and understands ghost in 60
seconds.

### Order rationale

Chunks 1 and 2 are foundational and risk-free. Chunk 3 is the
disruptive one and depends on chunk 2 (you want fingerprints in place
before you nuke the topic cache). Chunk 4 is independent but feels
weird to do before 3. Chunk 5 last because earlier chunks keep moving
the surface.

Each chunk gets its own plan, execution, verification, and commit. You
can stop after any chunk and ghost still works.
